## Part 1: Strategic Overview

### 1. Executive Summary
The Search Platform is the universal discovery layer for the CYBERMIND CyberOS. It enables rapid, secure, and semantic retrieval across all domain modules (CTI, Identity, SOC, Knowledge Graph) while enforcing strict Zero Trust and multi-tenant isolation policies on every query.

### 2. Vision & 3. Design Goals
To provide a unified, federated search experience that seamlessly blends lexical and semantic retrieval without ever becoming the operational source of truth.
- **Goals:** Provider-agnostic storage abstraction, real-time eventual consistency via domain events, and deep integration with RAG pipelines.

### 4. Guiding Principles
- **Constitutional Alignment (Rule #18):** Search is a discovery layer, not a data store. It indexes information for retrieval but never becomes the system of record. Every indexed document must remain traceable to its authoritative owning domain.

## Part 2: Domain-Driven Design (DDD)

### 5. Ubiquitous Language
- **Index:** A logical partition of searchable documents.
- **Document:** A denormalized, flattened representation of an operational entity.
- **Security Trimming:** The process of stripping unauthorized documents from search results before they reach the user.
- **Hybrid Retrieval:** Blending keyword (BM25) and vector (KNN) search scores into a single ranked result list.

### 6. Bounded Contexts & 7. Context Map
- **Dependencies (Upstream):** Identity (AuthZ/RBAC enforcement).
- **Producers (Downstream):** Every platform domain (CTI, SOC, Knowledge Graph) via Event Bus.
- **Consumers (Downstream):** AI Platform (RAG), Analyst Workbench.

### 8. Domain Model & 9. Search Object Taxonomy
Search models flat **Documents**. Taxonomies map 1:1 with domain aggregates:
- `IdentityDoc` (Users, Orgs)
- `ThreatIntelDoc` (Threat Actors, Campaigns, IOCs, Advisories)
- `OperationsDoc` (Alerts, Cases, Incidents)
- `KnowledgeDoc` (Articles, Playbooks)

## Part 3: Architecture & Search Lifecycle

### 10. Query Lifecycle
1. **Query Received:** API Gateway authenticates the user.
2. **Expansion:** Synonyms and semantic vectors are generated (via AI Platform embedding service).
3. **Execution (Hybrid):** Lexical + Vector search executed against the abstract Search Engine.
4. **Security Trimming:** Results filtered against the user's `tenant_id` and RBAC claims.
5. **Ranking:** Final scores calculated (Lexical + Semantic + Recency + Popularity).
6. **Result Returned:** Snippets and highlights delivered to the client.

### 11. Indexing Architecture & 12. Document Model
- **Event-Driven:** Search subscribes to platform-wide events (e.g., `ThreatPublished`, `AlertCreated`).
- **Document Model:** Every document contains immutable metadata: `id`, `domain`, `owner`, `tenant_id`, `classification` (TLP), `vector_embedding`, and `source_reference`.

### 13. Ranking Strategy & 14. Relevance Model
Ranking is composite and transparent:
`Final Score = (Lexical Score * 0.4) + (Vector Score * 0.4) + (Business Logic [Recency, Confidence] * 0.2)`

### 15. Hybrid Search Architecture
Supports Simultaneous Lexical (TF-IDF/BM25) and Vector (Dense embeddings) retrieval.

### 16. Semantic Search & 17. Vector Search
Embeddings generated by the AI Platform are stored alongside document text. Vector KNN (K-Nearest Neighbors) enables searching by concept (e.g., "lateral movement techniques") rather than exact keywords.

### 18. Query Expansion & 19. Security Trimming
- **Expansion:** Automatic inclusion of MITRE ATT&CK aliases.
- **Security Trimming:** Zero Trust enforcement. The Search Platform injects a `filter { tenant_id = X AND access_level <= Y }` into every physical query.

### 20. Faceting & 21. Aggregations & 22. Analytics
Provides real-time aggregations (e.g., "Count alerts by severity") and captures query analytics (e.g., "Zero-result queries") to improve relevance models.

## Part 4: Integrations

### 23. Event Model
Search only **consumes** events. It does not publish operational events.
- **Consumed:** `*Published`, `*Updated`, `*Deleted`.

### 24. AI Integration
- AI Platform uses the `Semantic Search API` for RAG. Search acts purely as a retrieval engine and does not execute any LLM inference natively.

### 25. Knowledge Graph Integration
- Search retrieves candidate nodes. It does not traverse edges. If a user searches for a Threat Actor, Search returns the Actor document; the client/AI then queries the Graph to find connected IPs.

### 26. CTI Integration
- CTI publishes validated Intelligence Objects, which are instantly indexed to enable cross-domain threat hunting.

### 27. Public APIs
- `POST /api/search/query`
- `GET /api/search/autocomplete`
- `POST /api/search/federated`

## Part 5: Infrastructure & Operations

### 28. Storage Abstraction
- Defined by a generic `SearchRepository` interface. Implementation-agnostic (could be Elasticsearch, OpenSearch, Solr, Typesense, or PostgreSQL pgvector).

### 29. Multi-Tenant Strategy & 30. Security Architecture
- Strict logical isolation via mandatory `tenant_id` routing parameters on every index and query.

### 31. Performance Strategy & 32. Scalability Strategy
- Horizontally scalable indices with sharding and replication.
- Ingestion occurs via debounced BullMQ queues to prevent mapping explosions during mass data imports.

### 33. Disaster Recovery, 34. Monitoring, & 35. Observability
- Search clusters can be completely rebuilt from scratch by triggering a re-index from the authoritative domain databases.
- OpenTelemetry tracks `search.query.latency`, `search.index.lag`, and `search.zero_results.count`.

### 36. Audit Strategy & 37. Data Lifecycle
- Documents adhere to the retention policy of their owning domain. If SOC deletes a 3-year-old alert, the `AlertDeleted` event removes it from the index.
